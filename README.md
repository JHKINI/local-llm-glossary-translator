# 반도체 용어 번역기

소형 LLM이 반도체 용어를 일관되게 번역하도록 용어집을 주입하고, 적용 결과를 화면에서 확인할 수 있게 만든 로컬 번역 서비스

![데스크톱 화면](local-llm-glossary-translator/frontend/result1.png)
![모바일 화면](local-llm-glossary-translator/frontend/result2.png)

> 도메인 용어집을 적용한 **번역 프로토타입**입니다. 번역 성능을 입증하는 도구가 아니라, 용어집 주입 방식이 용어 일관성에 미치는 영향을 작은 실험으로 확인한 프로젝트입니다. 실험 범위와 한계는 [5. 실험](#5-실험)에 적었습니다.


## 1. 프로젝트 개요

### 목적

소형 모델은 일반 문장은 무난하게 번역하지만, 도메인 용어는 표기가 흔들립니다.

- 기본 설정에서 같은 문장을 4번 번역하면 4가지 결과가 나왔습니다.
- 용어집 없이 번역하면 "수율"이 "수율률"로 나오는 등 정해진 표기와 다른 번역이 나왔습니다.

반도체 QC 문서는 수율, 로트, 관리도, 규격 이탈처럼 표기가 정해진 용어가 많아서, 이 문제를 직접 줄여 보고 싶었습니다. 로컬 모델을 쓰면 문서가 외부로 나가지 않고, 용어집을 직접 통제할 수 있습니다.

### 목표

- 용어집을 프롬프트에 넣어 용어 표기를 통일하되, 용어와 무관한 문장은 건드리지 않기
- 어떤 용어가 실제로 적용됐는지 화면에서 확인할 수 있게 만들기
- 용어집 적용 방식을 실험으로 비교하고, 결과와 한계를 있는 그대로 기록하기

### 기술 스택 · 개발 환경

| 구분 | 사용 기술 |
| --- | --- |
| Language | Python 3 · JavaScript |
| LLM | Ollama · qwen3.5:4b |
| Backend | FastAPI · httpx · Pydantic |
| Frontend | React 18 · Vite · CSS (Grid · Flex · media query) |
| 실험 기록 | Excel (문장 세트, 자동 집계 수식) |
| 환경 | Windows · RTX 3080 10GB · Swagger UI |

## 2. 설계

### 구조

```
브라우저 (React · :5173)
   │  POST /translate   { text, source, target, glossary }
   ▼
FastAPI (:8002)
   │  원문에 나온 용어만 골라 프롬프트에 추가
   ▼
Ollama (:11434)   qwen3.5:4b · temperature 0 · think 끔
```

### API

| Method | URL | 설명 | 응답 |
| --- | --- | --- | --- |
| GET | `/` | 서버 상태와 모델 이름 | 200 |
| POST | `/translate` | 번역 + 적용된 용어 + 속도 정보 | 200 / 502 |

**요청**

| 필드 | 설명 |
| --- | --- |
| `text` | 번역할 원문 |
| `source` · `target` | 언어 코드 (ko, en, ja, zh, es, fr, de) |
| `glossary` | 용어집 `{ "원문 용어": "번역어" }`. 비워도 됨 |

**응답**

```json
{
  "translated": "다음 검사 전에 수율을 확인해 주세요.",
  "meta": {
    "model": "qwen3.5:4b",
    "temperature": 0,
    "used_glossary": { "yield rate": "수율" },
    "total_sec": 0.41,
    "load_sec": 0.01,
    "eval_rate": 98.4
  }
}
```

`meta.used_glossary`는 받은 용어집 중 **서버가 실제로 프롬프트에 넣은 용어**입니다. 화면의 형광펜과 "적용된 용어" 목록이 이 값을 사용합니다.

**에러 응답**

| 상태 | 의미 |
| --- | --- |
| 422 | 요청 형식 오류 (Pydantic 검증 실패) |
| 502 | Ollama 호출 실패 (꺼져 있거나 응답 없음) |

**환경 변수**

| 이름 | 기본값 |
| --- | --- |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | `qwen3.5:4b` |
| `TEMPERATURE` | `0` |

## 3. 주요 기능

### ① 용어집 주입 · 핵심

- 용어집 전체가 아니라 **원문에 실제로 나온 용어만** 시스템 프롬프트에 `- yield rate = 수율` 형태로 추가
- 영어 용어는 단어 경계와 복수형(s, es)까지 확인. `slot` 안의 `lot`은 찾지 않음
- 한국어 용어는 조사가 붙어도 찾도록 포함 여부로 판정 ("수율을", "웨이퍼가")
- 용어가 하나도 없으면 프롬프트에 아무것도 추가하지 않음
- temperature 0 고정으로 같은 입력은 같은 결과 (실험 재현용)

### ② 적용 결과 확인

- 번역문에서 용어집 번역어를 형광펜으로 표시, 마우스를 올리면 원문 용어 표시
- "적용된 용어" 목록에서 용어마다 번역문에 실제로 들어갔는지 표시 (반영됨 / 번역문에 없음)
- 모델이 용어를 따르지 않은 경우를 사용자가 바로 알아볼 수 있음

### ③ 번역 화면

- 한국어 ↔ English, 언어 바꾸기 시 번역문을 원문 칸으로 올려 재번역
- 반도체 용어집 10개 켜기/끄기, 사용자 용어 추가
- 한국어 → 영어 번역에서는 용어집 key와 value를 자동으로 뒤집어서 적용
- Ctrl+Enter 번역, 복사, 글자 수 표시 (최대 2000자)

### ④ 상태 안내 · 반응형

- 서버 연결 상태 표시, 오류 원인별 안내 (서버 꺼짐 / Ollama 응답 없음 / 요청 형식 오류)
- 첫 요청은 모델을 메모리에 올리느라 오래 걸리므로, 번역 시간 대신 "처음 요청이라 모델을 불러왔어요."로 표시. 속도 수치는 "상세 정보"에 따로 표시
- 모바일 우선 CSS. 860px 이상에서 원문/번역문 좌우 배치, 터치 대상 44px 이상

## 4. 데이터 흐름

'번역하기' 요청 한 건의 흐름

```
브라우저
  ① 번역 방향에 맞게 용어집 구성 (한→영이면 key/value 뒤집기)
  ② POST /translate
        ▼
FastAPI
  ③ Pydantic 검증                          실패 → 422
  ④ 원문에 나온 용어만 선택 (used)
  ⑤ 시스템 프롬프트 + used 용어 추가
  ⑥ Ollama /api/chat 호출                  실패 → 502
        ▼
Ollama (qwen3.5:4b)
  ⑦ 번역 생성
        ▼
FastAPI
  ⑧ translated + meta(used_glossary, 시간, 속도) 반환
        ▼
브라우저
  ⑨ 번역문에서 used 번역어를 찾아 형광펜 표시
  ⑩ "적용된 용어" 목록: 번역문에 들어갔는지 검사해 반영됨 / 번역문에 없음 표시
```

## 5. 실험

### 조건

- 문장 15개: 용어 포함 10문장, 용어집과 무관한 대조군 5문장
- 영어 → 한국어, temperature 0, 조건당 1회 실행
- 채점: 기대 용어가 정해진 표기로 들어가면 O (용어가 2개면 둘 다 맞아야 O)
- 조건 **A** 용어집 없음 · **B** 용어집 10개를 항상 전부 추가 · **C** 원문에 나온 용어만 추가 (현재 서비스 방식)

### 결과

| | A 용어집 없음 | B 전체 추가 | C 필터 적용 |
| --- | --- | --- | --- |
| 용어 정확 (용어 포함 10문장) | 2 / 10 | 10 / 10 | 10 / 10 |
| 대조군 5문장 중 A와 동일 | - | 1 / 5 | 5 / 5 |

B와 C를 비교하면 용어 포함 10문장 중 6문장은 동일하고 4문장은 표현이 달라졌습니다.

| 원문 | A 용어집 없음 | C 필터 적용 |
| --- | --- | --- |
| Please check the yield rate before the next inspection. | 다음 검사 전에 수율**률**을 확인해 주세요. | 다음 검사 전에 **수율**을 확인해 주세요. |
| The control chart shows an upward trend in defect density. | **제어 차트**는 결함 밀도의 상승 추세를 보여줍니다. | **관리도**는 결함 밀도가 상승하는 추세를 보여줍니다. |
| A corrective action was approved to reduce the defect rate. | 결함률을 낮추기 위한 **교정 조치**에 승인이 내려졌습니다. | 결함률을 줄이기 위한 **시정 조치**가 승인되었습니다. |

### 해석

- A의 2/10은 오역률이 아니라 **정해진 표기와의 일치율**입니다. "에칭", "제어 차트", "교정 조치", "lots"처럼 업계에서 통용될 수 있는 다른 표기도 X로 채점했습니다. 명백한 오역은 "수율률"이었습니다.
- B는 용어를 모두 맞췄지만, 용어와 무관한 대조군 5문장 중 4문장의 번역이 달라졌습니다. 프롬프트에 관련 없는 용어가 붙으면 다른 문장의 표현도 흔들릴 수 있다는 관찰입니다.
- C의 대조군 5/5는 용어가 없는 문장에 프롬프트를 바꾸지 않아서 생긴 결과입니다. temperature 0에서 같은 프롬프트는 같은 출력을 내므로, 필터가 의도대로 동작하는지 확인한 것이며 품질이 좋아졌다는 뜻은 아닙니다.

### 한계

- 문장 15개, 모델 1개, 조건당 1회의 소규모 관찰입니다. 일반화할 수 있는 성능 수치가 아닙니다.
- 채점은 직접 했고, 업계의 다른 표기를 X로 처리한 기준이 A의 점수를 낮춥니다.
- 용어 O/X는 문장의 의미를 보지 못합니다. C에서 `lot 42`가 "42 로트"로 번역되어 "로트 42"와 달리 읽힐 수 있고, `recipe`가 "공정"으로 바뀐 문장도 있었는데, 둘 다 용어 채점은 O였습니다.
- 한국어 → 영어는 용어집 방향 뒤집기를 구현했지만 품질 실험은 하지 않았습니다.

### 참고 측정

내 PC(RTX 3080 10GB)에서 몇 차례 번역했을 때 생성 속도는 초당 약 93~109 토큰이었습니다. 정식 벤치마크가 아닙니다.

## 6. 문제 해결 기록

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 용어집을 보내도 번역이 그대로 | 요청 모델에 `glossary` 필드가 없어서 Pydantic이 값을 조용히 무시 | `glossary: dict[str, str] = {}` 필드 추가 |
| 용어가 없는 문장에서 500 오류 | Ollama 요청 데이터를 `if used:` 안에서 만들어서, 용어가 없으면 변수가 생기지 않음 (UnboundLocalError) | 요청 데이터 생성을 블록 밖으로 옮겨 용어 유무와 관계없이 같은 구조로 처리 |
| 용어집을 넣었더니 용어 없는 문장도 번역이 달라짐 | 모든 요청에 용어집 10개를 붙여서 프롬프트 자체가 달라짐 | 원문에 나온 용어만 추가. 대조군 5문장이 A와 모두 동일해짐 |
| 한국어 원문에서 용어를 못 찾음 | `\b`는 "수율을"처럼 조사가 붙은 한글에서 단어 경계로 동작하지 않음 | 한국어 용어는 포함 여부로 판정, 영어는 `\b` 유지 (`slot`의 `lot` 오탐 방지) |
| 같은 문장이 매번 다르게 번역 | 기본 temperature의 무작위성 | temperature 0 고정. 단 오역도 고정되므로 용어집으로 보완 |

## 7. 결론

### 배운 점

| 주제 | 내용 |
| --- | --- |
| 재현 가능한 실험 | temperature를 고정해야 조건 간 차이를 비교할 수 있다. 대조군을 두어야 "용어 외 문장에 영향이 없는지" 확인할 수 있다 |
| 프롬프트는 입력의 일부 | 프롬프트가 조금만 달라져도 관련 없는 문장의 출력이 바뀐다. 필요한 정보만 넣는 필터가 중요하다 |
| 검증 가능한 UI | 모델이 용어를 따랐는지 믿지 않고, 서버가 적용한 용어와 번역문을 대조해서 보여 준다 |
| 사용자에게 보이는 수치 | 첫 요청의 모델 로딩 시간을 번역 시간처럼 보여 주면 오해한다. 지표는 의미에 맞게 분리한다 |
| 결과를 정직하게 기록 | 소규모 실험이라는 한계와, 점수가 좋아진 이유가 구조 때문인지 품질 때문인지를 구분해서 적는다 |

### 개선할 점

| 문제 | 개선 방법 |
| --- | --- |
| 소규모 실험 (15문장, 1회) | 문장 수를 늘리고 반복 실행해 결과 안정성 확인 |
| 자가 채점, 문장 의미 미평가 | 채점 기준 문서화, 다른 사람의 평가, 의미 평가 항목 추가 |
| 모델 1개만 사용 | 9b 모델, 번역 전용 모델과 비교 |
| 모델이 용어를 따르지 않으면 사용자가 직접 확인 | 번역 후 용어 누락 검사, 자동 재요청 |
| 한국어 → 영어 품질 미평가 | 같은 방식의 문장 세트로 실험 |
| 용어집이 코드에 고정 (10개) | CSV 업로드, 서버 저장 |
| 테스트 코드 없음 | 용어 필터 단위 테스트 (영어 복수형, 한글 조사, 오탐) |
| 로컬 실행만 가능 | Docker Compose로 백엔드와 Ollama를 묶어 배포 |

**단순한 번역 호출을 넘어, 용어 일관성 문제를 실험으로 확인하고 서비스 화면까지 연결한 로컬 번역 프로토타입**

## 8. 실행 방법

필요한 것: Python 3.10 이상, Node.js 18 이상, [Ollama](https://ollama.com)

```
# 1. 모델 받기
ollama pull qwen3.5:4b

# 2. 백엔드 (Swagger: http://127.0.0.1:8002/docs)
cd backend
pip install fastapi uvicorn httpx
uvicorn main:app --port 8002

# 3. 프론트엔드 (http://localhost:5173)
cd frontend
npm install
npm run dev
```

백엔드 주소가 다르면 `frontend/.env`에 `VITE_API_URL=http://127.0.0.1:8000` 을 적습니다.

```
local-llm-translator/
├─ backend/        main.py
├─ frontend/       React 프로젝트 (Vite)
|      └─ result/    문장 세트 실험 엑셀, 화면 캡처, 시연영상
└─ README.md
```
